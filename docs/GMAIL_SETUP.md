# Gmail 自动记账配置

此方案不要求 Apple 账号。需要你自己的 Gmail 账号、已部署的 HTTPS 后台和后台持久化存储。**尚未连接你的 Gmail，也未创建定时任务。**

## 1. 配置后台

在网站托管平台安全的环境变量设置中配置：

- `EMAIL_WEBHOOK_SECRET`：随机高强度密钥（至少 32 字节）。例如在你自己的终端运行 `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`，自行保存输出，不要提交 Git 或发到聊天中。
- `DATA_DIR`：托管平台持久化磁盘上的目录，例如 `/var/data/money-app`。

重启后台后，未带密钥访问 `/api/email/transactions` 必须返回 HTTP 401。浏览器页面的邮件栏不会显示“已连接”，直到真实同步成功。

## 2. 在 Google 中配置脚本

1. 打开 Google Apps Script（script.google.com），新建私人项目。
2. 把仓库 `integrations/gmail.gs` 的全部内容复制到脚本编辑器中并保存。
3. 在项目设置 → 脚本属性中新增以下三个属性，**不要在代码里硬编码密钥**：

| 属性 | 值 |
| --- | --- |
| `APP_URL` | 已部署的 HTTPS 网站根地址，不带路径 |
| `EMAIL_WEBHOOK_SECRET` | 与后台相同的私人密钥 |
| `GMAIL_QUERY` | 你的银行真实发件地址 + 消费通知主题筛选 |

查询格式示例：`from:你的银行通知地址 subject:你的交易通知标题`。先在 Gmail 搜索框验证，仅包含目标信用卡的消费通知。不要照抄虚构的银行地址或使用全邮箱查询。

4. 在编辑器选择并运行 `syncCreditCardEmails`。Google 会要求授权 Gmail 读取权限和外部请求权限。仅对你自己的项目授权；不需要把脚本部署为公开 Web App。
5. 如果 Google 或组织政策阻止授权，请停止并解决账号权限；不要忽略来源不明项目的安全提示。
6. 在 Apps Script「触发器」中为 `syncCreditCardEmails` 创建「时间驱动」触发器，例如每 15 分钟。仅手动运行一次不会持续监控。
7. 在脚本执行记录中确认无错误；不要在日志中打印邮件正文或密钥。

## 3. 在 App 同步

1. iPhone 打开已部署的 App，进入「邮件」。
2. 输入同一个后台密钥（仅保存在当前会话中）。
3. 点击「同步待确认交易」。同一 Gmail 消息 ID 不会重复入账。
4. 点击每条待确认交易，核对商户、金额、日期及分类，保存即确认。删除的邮件交易会在此设备上记住，之后同步不会再次出现；恢复老备份可能改变此状态。

后台只接受 CAD 明确标识的交易进入本机账本。非 CAD 或不明 `$` 币种提示跳过，请核对原文并手动录入。当前不做自动汇率换算。

## 4. 数据、安全和排错

- 邮件正文会发送到你自己的后台用于解析；仅归一化交易写入磁盘。Google Apps Script 访问权限是 Gmail 服务所需的广泛读取权限，并非只授权一个标签。
- 密钥可读取后台全部已导入交易。仅供你和受信任家人使用。泄露时请在后台、Apps Script、各手机中同时更换。
- 401：密钥未设置或不一致。500：存储目录不可写或持久化盘异常。不要通过公开关闭鉴权解决。
- 同步成功但没有记录：先核对 Gmail 查询结果、触发器运行记录、CAD 标识及邮件格式。
- 脚本使用 7 天重叠窗口避免短暂失败漏记，最多查询 100 个会话；大量通知或停用超过 7 天应人工核对。
- 银行通知格式尚未通过你的真实样本验证。可提供**脱敏**的金额、日期和商户附近格式供后续改进，勿提供卡号、验证码或邮箱凭证。
